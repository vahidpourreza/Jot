# Jot

A personal Windows notes app built with .NET 10. The UI uses the existing design system's IRANSansX fonts, 19 accent presets, neutral light/dark surfaces, and Lucide icons.

## Current build

**Development build: `dist\Jot-dev-editorcn\Jot.exe` (v1.7.0, 2026-10-05).** Keep its adjacent files together and quit an older running Jot before opening it. This iteration is development-only: do not build another installer unless the user explicitly requests one. The existing installer below remains v1.5.0 and does not contain these changes.

This iteration replaces the custom note editing engine with **editorcn 0.3.4, Tiptap 3.31.4 and React 19.3.0**, bundled locally inside the existing WebView. It uses the actual editorcn block editor, slash suggestions, selection bubble and drag handles, plus Jot's compact toolbar and native clipboard integration. Undo, selections, tables and rich-document commands are now ProseMirror transactions. Each open note retains its own editor state/history. The header, tabs, Home, Trash, document title/emoji, file identity and native Windows controls are preserved. See TESTING.md for verification status; Notepad-level performance remains a target, not a claimed result.

**Upgrade safety:** opening an older library creates and verifies `jot.db.before-v3.bak`, then advances its version to 3 without rewriting note HTML. Retried upgrades preserve that earliest backup and create a fresh uniquely named snapshot. After upgrading, use **Jot 1.7 or newer**; older builds refuse the library rather than stripping new editor content. New `.jot` saves use file version 2; existing version-1 files still open, and `.txt` remains unchanged. Merely opening an old note/file does not rewrite it or mark it dirty. Unrecognized formatting opens read-only with its original preserved. Windows file associations are not automatically changed by this development build. See [editor migration and recovery](docs/editorcn-migration.md).

### Last packaged release

For end users, run **dist\installer\Jot-Setup-1.5.0-win-x64.exe** (approximately 334 MiB). It bundles .NET/WPF, SQLite and a private WebView2 runtime, installs per-user without elevation, and requires no separate prerequisite installation or setup-time download. Quit an existing Jot before installing. Uninstall preserves notes and backups. The installer is currently unsigned, so Windows may show an unknown-publisher/SmartScreen warning.

For repeatable releases, run **scripts/release.ps1**; use `-Verify -TestInstaller` for full offscreen app and isolated installation checks. Runtime downloads are cached locally. A cached `-NoRestore` build took about 112 seconds in validation. See [releasing](docs/releasing.md) for prerequisites on the developer machine, cache behavior, runtime updates and verification limits.

Normal launches restore recorded notes in the selected Open mode, with saved positions/sizes constrained to an available monitor's work area. Standalone-note snapshots exclude individually closed, hidden and minimized note windows. Closing the workspace with its window X saves its open note tabs, active tab, Settings-tab state and normal window bounds before hiding it; a later Quit retains that workspace snapshot. The next launch restores its notes as tabs or separate windows according to Open mode, and reopens Settings when it was left open. Explicitly closing a note tab removes it from the workspace session but keeps the note in the library. A saved workspace can therefore open Home on startup; otherwise Home remains an explicit destination. With no saved notes or Settings tab, Jot creates one blank note without changing existing notes.

Closing the last open app window fully quits Jot and removes its tray icon. Home/Settings, notes and image viewers count; minimized windows keep the app running, while hidden tray/cache windows do not. Pending saves/images finish first, and a failed shutdown keeps a recovery window open. Closing standalone notes individually still excludes them from restoration. Image viewers are not reopened. Explicit `--tray` startup remains available for a deliberate background-only launch. The first launch migrates existing JSON notes to SQLite; after switching, do not return to the older JSON-based app.

The raw developer publish bundles .NET but uses the machine's WebView2 installation; the installer above bundles both. The technical OS minimum is Windows 10 build 19041 or later on an x64-compatible system. This app uses WebView2's WPF composition control with anti-aliased clipping, a subtle border, and a soft shadow. It no longer uses a jagged Win32 region for its corners.

## Text size, tab switching, tables and Trash

- **Ctrl + mouse wheel** over a note changes only that note's font size, not the whole window. **Ctrl++ / Ctrl+−** also work; **Ctrl+0** removes the override and follows Settings → Writing defaults. Existing 13–24px limits remain. Rich text, selection and other notes are unchanged. Keyboard bindings can be changed in Settings → Keyboard shortcuts.
- **Hold Ctrl and press Tab** to preview recently used tabs with their title, emoji and note color. Press Tab again to cycle, use Shift to reverse, then release Ctrl to switch. Escape cancels; Home and open Settings are included. Selecting a preview uses the existing save-before-switch path. Custom shortcuts remain supported; modifierless shortcuts use Enter to confirm.
- **Table** in the toolbar opens a row/column chooser; `/table` inserts a quick 3×3 table. Table options include rows/columns, header rows, merge/split and removal. Tab / Shift+Tab moves between cells; Tab at the last cell adds a row. `/divider`, `/inline code`, headings, lists, checklists, quotes and highlighted code blocks use the new editor. Markdown-style typing such as `# ` and `- ` works too. This is rich-text editing, not a raw Markdown editor or a new `.md` file format.
- **Home → Trash** shows deleted notes, including older recovery copies. Search, restore and permanent deletion support multiple selected items. Permanent deletion requires confirmation; nothing expires automatically. Restore preserves note content and preferences but detaches any saved-file link, preventing automatic writes to an external file. Saved files are never deleted by Trash.

Windows, not Jot, controls whether its notification icon stays beside the clock or inside the `^` overflow. Drag Jot's icon out of that overflow, or enable it in Windows taskbar settings. A stable installation path helps Windows retain the choice; moving unsigned development builds may reset its identity. Jot does not modify unsupported tray registry settings or force the icon's visibility. See [Microsoft's notification-area guidance](https://learn.microsoft.com/en-us/windows/win32/shell/notification-area).

## Home and work windows

Home is a note library with a permanent first Home tab bearing the app logo, familiar minimize/maximize/close controls, and a separate app bar for New note, folders, grid/list layouts and Settings. Wide windows show a library sidebar; compact windows keep the same destinations in the folder control. Search covers titles, content and folder names, folding Persian/Arabic keyboard variants and digits without rewriting stored notes. Cards keep their note's top accent strip and neutral body. Untitled notes have no generated heading. A small pin identifies notes pinned to the top; editing actions stay in the right-click/context-key menu: Open, Open in new tab, Pin to top/Unpin, Select, Rename, Move to folder, Copy, Export and Delete.

Settings opens once as a dedicated, closable tab in the same persistent workspace. Switching among Home, Settings and notes preserves maximized state, search, folder selection and grid/list preference. Closing Settings returns to an open note or Home without closing the workspace. Maximize uses the monitor work area, keeping the Windows taskbar visible, and Restore returns to the previous window bounds. Normal Open follows the selected Open mode; Open in new tab opens an editor inside Home and safely transfers any existing editor without duplicates.

The app interface is English-only; notes still support Persian and English together, with automatic paragraph direction and a keyboard-aware empty caret. Each note has a document heading with an editable title and emoji above its writing body. An empty title displays Untitled; the body has no placeholder or saved/saving badge. Library autosave continues quietly, while title-saving failures offer Retry. File-backed notes show the linked filename and file status separately beneath the heading so library autosave is not confused with saving the separate file.

Mixed-language handling now recognizes Persian sentences that start with English technical identifiers, and isolates English/technical expressions so their internal order remains readable. Read-only titles/previews use the same rules. **More → Direction → Auto / LTR / RTL** provides a per-paragraph override for ambiguous cases, with Undo and save/reload support. This does not change the app language, reorder stored characters, or add hidden direction characters to plain-text Copy. See [mixed-language writing](docs/mixed-language-writing.md) for coverage and limits.

The note header has **+ New note** on the left and **More → Pin → Minimize → Maximize/Restore → X (close note)** on the right. The app-logo/Home button, old grip, and shutdown controls are removed from notes. Use the square maximize icon to fill the current monitor's work area while leaving the Windows taskbar visible; click it again to restore the entire window's prior small size and position. Fullscreen switching is immediate, without a resize animation. Explicit native pixel-bound restoration returns the whole window to its prior compact size. Drag the blank fullscreen header downward to restore that size under the pointer and continue Windows window movement; ordinary clicks, small jitters, and header buttons do not trigger this. Other menu/toolbar/header transitions are unchanged. Maximized windows use the familiar overlapping-squares restore glyph without a solid dark tile. It does not enable Pin or change another note. Fullscreen remains available when hiding/reopening that window in the same session; app restart uses the original compact bounds rather than unexpectedly restoring a monitor-sized note. Windows-native keyboard maximize uses the same work-area behavior. Open the index through **More → Home**. X closes that note window while another app window remains open; closing the last window quits Jot. Standalone notes have no tab controls; their header + uses the app-wide new-note destination. More borrows the Windows Sticky Notes visual style—a single-row color palette with visible swatch separators and flat icon/text rows—with **Home**, small **Light mode / Dark mode** text, **Font size**, **Line height**, **Export**, **Copy**, and **Delete**. The Appearance and plain-text-copy shortcuts are removed from notes; app settings remain in the index. All 19 colors are visible in one row, ordered from warm reds through yellows/greens/blues to purples/pinks, with neutral last. Swatches have visible gaps/outlines and narrow with the window; all 19 remain visible without scrolling. Left/right arrows navigate them; Home/End reach the first/last color. In short windows only the options list scrolls, keeping every color visible and leaving room outside the panel to dismiss it. Escape also dismisses it. Pin remains opt-in and uses a filled glyph when active, without a solid background. The top document formatting and image controls stay neutral-colored.

The document heading edits the note title directly; when it is empty, library and tab labels fall back to the first content line. The writing surface stays neutral: the active note uses a colored sticky-note header, while an inactive note shows a more visible 8px colored top strip. The colored header expands/collapses over 160ms without shifting the writing area. More visibly reveals its full height over 260ms and closes over 200ms, with an opaque surface so text does not bleed through. Interrupted motion continues from the current frame. Closing controls become non-interactive immediately; reduced-motion preferences disable these effects. Pin hides with the other inactive header icons, even when pinned; the whole group returns on hover/focus. Header hover targets sit below the 8px strip in both themes. Font size is displayed in pixels and stays within 13–24px. At either limit, the disabled button uses a normal cursor and a minimum/maximum tooltip, not a loading cursor. Only explicitly busy actions use the wait cursor. Native window corners are reduced to 6px, with matching 5px content clipping and compact 6px popovers.

This is editor-only: app typography, saved font sizes/line heights, rich formatting, custom fonts and note content stay unchanged. No custom selection overlay replaces the browser's normal editing behavior.

English, Persian words with ZWNJ, mixed-direction runs and rich formatting are included in the regression fixtures. The WPF/WebView2 composition adapter now forwards the second mouse press only once; previously the SDK's duplicate forwarding made a double-click act like a triple-click. The fix does not add a custom word parser or rewrite note contents. Standard word navigation/deletion, Home/End, selection replacement, Cut/Undo and IME composition remain supported.
- Right-click inside a note for a Jot-styled editing menu: Undo/Redo, Cut, Copy, plain-text Paste, Direction (Auto / LTR / RTL), and Select all. The Direction label and equal-height option buttons are vertically aligned, with centered text and soft border-free selection. The existing More → Direction controls remain available. Right-click an image for Open image, Copy image, and undoable Remove image. Shift+F10 opens it from the keyboard; arrows/Home/End navigate, and Escape dismisses it. Clipboard reads happen only on Paste. Cut removes content only after successful copying; a failed, cancelled, or stale operation leaves it intact.
- Generic browser context menus are disabled throughout Jot. Blank chrome and ordinary window controls do not open a browser menu. The app icon in the workspace opens file commands and Settings on right-click; note tabs have a separate note-actions menu. Search/title/group fields have a compact Cut/Copy/Paste/Select all menu that preserves selection and works inside dialogs. The image viewer has a content-only menu for Copy, zoom, Fit/100%, and fullscreen.
- The More panel now uses a distinct neutral surface in both themes, keeping its existing options, colors and transitions.
- Click the **emoji beside the document title**, or choose **More → Note emoji**, to change the note's symbol. Note identities are emoji-only, with 📝 as the default; Lucide icons remain on toolbar buttons and app controls. The local **Unicode Emoji 18.0** catalogue contains **3,963 fully qualified emojis**, including supported skin-tone combinations. Search by name, filter by category or skin tone, or paste a supported complete emoji; Win+. also opens Windows' own picker. Results are paged in groups of at most 96 so the full catalogue does not create thousands of controls at once. No network lookup is needed. Older saved Lucide note-icon IDs remain readable and display their mapped emoji without being rewritten merely by opening the note. Newer emoji glyphs depend on Windows' installed emoji font and may appear as boxes or separate symbols on older systems. The chosen emoji appears in the heading, library and tabs and is retained in `.jot` files.
- **More → Alignment → Auto / Left / Center / Right / Justify** applies to the current or selected paragraphs. Auto follows paragraph direction; explicit alignment does not change the text or its direction. Changes support Undo/Redo and save/reload. New plain-text paste follows the destination paragraph's alignment.
- The **formatting toolbar is above the document**, beneath the window/tab header. It provides paragraph styles, bold/italic/underline/strikethrough, bullet and numbered lists, text color, alignment and image insertion. The upright T button shows or hides formatting controls and remembers the preference. Narrow windows can scroll the toolbar; underline and strikethrough also remain available through the selection bubble, writing commands and their existing editing shortcuts where assigned. Toolbar controls stay neutral and use familiar Lucide glyphs.
- The **Text / paragraph-style** control offers ordinary text, Heading 1–3, lists, checklists, quotes and code blocks. Type `/` to search writing commands near the caret; use Up/Down and Enter to choose, or Escape to keep the typed text. Slash suggestions do not open inside code or during IME composition. Selecting text shows editorcn's formatting bubble. These controls use Tiptap commands and ProseMirror history; Jot retains its native clipboard, mixed-language rules and plain-text paste policy. Bold, italic, underline and strikethrough can each be toggled off directly.
- **Settings → Writing defaults** controls app-wide font size (13–24px) and line height. New notes inherit these values until that field is changed in the note's More settings. Font size and line height are independent overrides; **Use default** removes only the chosen override and follows future app changes. Existing notes retain every saved value, including values equal to the former defaults, until the user chooses Use default. Toolbar visibility and always-on-top Pin remain per-note. Light/Dark mode remains app-wide. Line-height presets are 1.2×, 1.5×, 1.75×, 1.95×, 2.2× and 2.5×. Changing writing preferences does not rewrite rich HTML or paragraph direction.
- **Normal paste is plain text by default.** Ctrl+V prefers the clipboard's text/plain version and does not import source colors, fonts, highlighting, code-block backgrounds, headings or table styling. Line breaks, intentional blank/trailing lines, indentation, literal code characters and Persian/English text are preserved. Copy's plain-text fallback and saved plain text use logical line boundaries, so repeated Cut → Paste does not multiply blank paragraphs. Newly pasted plain lines use the note's effective font and line height without extra paragraph gaps; existing rich paragraphs are not restyled. HTML-only clipboard text is flattened into ordinary lines (table cells use tab separators), and active content is discarded. An empty clipboard does not change the note.
- Images appear as tiny inline previews (up to 72 × 48), without forcing a separate paragraph. Click one to open the original in a separate viewer: zoom in/out with a percentage, Fit, 100%, original-image Copy, and fullscreen. Scroll to zoom, drag to pan, or double-click to toggle Fit/100%. Manual zoom runs from 10% to 800%; Fit can go smaller for large images.
- The fullscreen button fills the image window's current monitor, without enabling always-on-top. Click it again to restore the previous bounds. The X closes the viewer. Zoom, Fit and 100% remain available through buttons and the image context menu; custom keyboard shortcuts are disabled. Viewer zoom never changes the stored or copied original.
- Image Copy uses the shared notification style for Copying, success and error states, without replacing the dimensions footer. Feedback does not resize the image viewport, alter zoom, or clamp either scroll position. A delayed scroll notification from Fit/focus cannot dismiss a newly opened image menu unless the viewport actually moved.
- Original image resolution is retained. PNG, JPEG, WebP, and GIF are supported, up to 8 MB each.
- Ctrl+C retains selected rich HTML, embedded images, and plain-text fallback. “Copy” copies the whole document. A selection containing one image supplies native PNG and Bitmap formats alongside its text, using the original resolution. There is no separate plain-text-copy action; normal Copy still supplies a plain-text fallback alongside rich content.
- The receiving application chooses which clipboard formats it supports; plain-text-only apps cannot retain images or formatting.
- For mixed text/images, HTML is used only to retain image placement: the surrounding text is unformatted and original images remain inline thumbnails. Image-only clipboard content still pastes as an image. This does not change outgoing Copy, which retains the note's current rich content and original images.
- Pasted public HTTPS image references are downloaded without cookies and embedded locally. Unavailable images get a visible placeholder and notification instead of silently disappearing. Sources requiring login may not be retrievable.
- Copy the complete note, change text size or line height, or export a standalone HTML note from the **note header → More** menu. The theme action states which mode it will switch to. Appearance settings are available from the index or tray Settings action. Strikethrough is available in the top toolbar, selection bubble and writing commands.

The note editor's right-click menu includes file commands after Select all, followed by **Home** in its own final row, using the same home icon as More. It saves the current draft before opening Home, reuses the existing index/settings window, and leaves the note open. It is also available when right-clicking an image.

## Folders and Home tabs

The library sidebar and compact folder menu provide All notes, Pinned, Unfiled, existing folders and New folder. Right-click a folder to create another folder, rename it or remove it. Removing a folder moves its notes to Unfiled; it does not delete them. Empty folders persist in the existing SQLite groups table, and new notes created while viewing a folder are filed there automatically.

**Pin to top** is library organization, separate from **Pin tab** and a window's always-on-top Pin. Library-pinned notes appear first and are available through the Pinned filter. Use **Select** (or Shift-click a card) to show checkboxes and the selected count, then Pin/Unpin, Move or Delete the selection. Select all applies to the current visible results. Changing the folder/filter clears selection. Bulk Delete requires confirmation, saves affected live editors and creates recovery copies before removing any selected notes. Associated `.jot`/`.txt` files stay on disk.

Tabs live in the Home window. The app icon is always the first, nonclosable Home tab, with no visible Home word. Right-click a library card and choose **Open in new tab**, Ctrl-click or middle-click it, or use the tab bar's **+** to create a note there. Normal card/list clicks and **New note** follow **Settings → Open mode**: Tabs or Separate windows. Tabs is the default when no choice has been saved; an existing explicit Separate windows preference is preserved. Changing the mode saves and moves open notes, including minimized windows, into that layout. A failed save preserves the old mode and editors. Explicit Open in window/New tab retain their chosen destination; the tab-strip + always creates a tab.

Switching tabs or returning Home waits for pending images and saves the active draft. Each note retains its own writing overrides, undo history, cursor and scroll state. Closing a note tab keeps its note in the library; closing the last note tab returns Home. Settings has its own closable tab and does not replace the permanent Home tab. Closing the workspace window with X saves the remaining note/Settings tabs for next launch; closing an individual tab deliberately removes only that tab from the saved workspace. Explicit Quit also saves every editor and workspace state. Startup restores work in the selected Open mode. Older floating-tab session records remain readable.

**Ctrl+Shift+T** reopens the most recently closed note tab, including its former position and pinned state. **Reopen closed tab** is also available from the tab context menu or by right-clicking unused tab-bar space. Jot keeps up to 20 closed note tabs during the current app session; this history is not restored after quitting. Deleted notes and notes already open elsewhere are skipped, and moving a note to a separate window is not treated as closing a tab. Settings is not part of note-tab history. The shortcut can be changed in Settings; if an older custom binding already used Ctrl+Shift+T, that choice is preserved and Reopen starts unassigned.

Drag a note tab left or right to change its position without changing the selected editor. The dragged tab follows the pointer while neighboring tabs move aside; the underlying tab order changes once, on drop. Right-click and choose **Pin tab** to keep it in the leading section immediately after permanent Home; **Unpin tab** returns it to the regular section. Pinned tabs keep a readable title, emoji and small pin marker rather than becoming icon-only buttons. Pinned and regular tabs can each be reordered within their section. Overflow scrolling and All tabs retain access to every note. Pins and tab order are saved with the workspace for the next launch. Pin tab never enables **Keep Jot on top** or **Pin to top** in the library. Escape immediately cancels an unfinished drag, releases its input/visual state and leaves the saved order unchanged. Drop transitions respect reduced-motion preferences.

Home and note title bars use familiar Windows controls: a line to minimize, a square to maximize, overlapping squares to restore, and X to close.

Windows-native maximize (including Win+Up and dragging to the top edge) uses the same work-area bounds and edge-to-edge app content as the maximize button, without the normal window's inset frame. The Windows taskbar stays available. Restore and dragging the maximized header return to normal bounds. **Keep Jot on top** pins the whole Home workspace above other apps, including when Home or Settings is selected; it does not pin a tab or alter separate notes' Pin values. The wide header has a pin button; compact windows retain the action in the app-icon and note-tab context menus. It is opt-in and remembered independently of library Pin to top.

All workspace tabs have visible bordered surfaces, including inactive tabs. Note tabs always combine a **soft tinted surface and a colored top accent strip**. The active tab has a stronger tint/border and slightly heavier title, without the former bright underline. There is no Tab colors setting; old Soft tint/Accent strip choices no longer affect the combined appearance. Saved note colors and text remain unchanged. Home and Settings stay neutral. The app-icon Home tab, tab strip, window controls, library and editor stay in one document: switching Home, Settings and notes does not navigate or reload the browser, capture screenshots, or animate over the text. Undo, cursor and scroll state stay in memory. Workspace notes have no duplicate New note/More header. Right-click a tab for Rename, Note emoji, More settings, Pin/Unpin tab, Keep Jot on top, Open in window (outward-link icon), Copy, Export, Close tab, Reopen closed tab and Delete note. Double-click its title (or press F2 while it is focused) to rename it without changing the note's text. More settings uses the same menu and controls as standalone notes, including color, theme and typography. Floating notes retain their own header and More menu. Drag a maximized workspace's blank header to restore its previous size under the pointer; double-click blank header space to toggle maximize/restore.

Overflowing tabs have previous/next buttons and an **All tabs** menu so early notes remain reachable without closing newer ones. Pinned tabs have their own scroll area and remain separate from the regular strip. In compact windows with pins, All tabs replaces the two scroll-arrow buttons to leave room for readable note titles. The menu includes every pinned and regular tab. Mouse-wheel, trackpad and keyboard navigation remain available.

## Separate note files

Right-click the **app icon** in the workspace or right-click inside a **note editor** for **Open file…** (Ctrl+O), **Save** (Ctrl+S) and **Save as…** (Ctrl+Shift+S). Save writes the associated file; Save as chooses a new path. Save actions are disabled when no note is active. `.jot` files preserve rich text, original embedded images, color, note icon, paragraph alignment and effective writing preferences; exporting inherited typography snapshots its current appearance without changing the note's library overrides. `.txt` files contain plain text; UTF-8/UTF-16 input is supported and saving writes UTF-8. The file limit is 32 MB. Opening the same file reuses its note.

The **note title and filename are independent**. Edit the title in the document heading or use Rename without renaming the linked file; tabs and library entries use that note title. The filename, extension, full-path tooltip and save status are shown separately below the heading. Save as chooses a new filename/location without replacing the chosen title or removing the previous file. A `.jot` file stores the title and emoji alongside its rich content, so another Jot instance can reopen those document details. A `.txt` file stores only plain body text: its Jot title, emoji, color and formatting preferences remain app-only metadata, not hidden additions to the text file. On first import, a text file's basename supplies its initial title; reloading it does not overwrite the title already chosen in Jot.

An unsaved dot and file-status label distinguish **Unsaved**, **Saving…**, **Saved**, and **Auto-save paused**. Tab/library markers also identify pending file changes. Library drafts still save automatically regardless of this status. **Settings → Auto-save files** is off by default; enable it to update already-linked files after one second idle. It never opens a save dialog for an unlinked note. With it off, use Save/Ctrl+S after editing. Text files track text changes, not formatting that `.txt` cannot store; rich files also track saved appearance and icon changes. Closing a linked note/tab/workspace flushes its latest editor draft and, when file auto-save is enabled, saves the file before releasing it. A failed required save keeps the note available.

Outside file changes and missing or locked destinations pause automatic saving and leave the library draft intact. Use Save as to preserve your local version at a different path. File replacement is checked against the expected content, including a race during commit: if a newer external version was displaced, it is retained in a sibling `.jot-recovery-*` file, and the error gives its exact location. That race is reported as a conflict, not a successful save; Jot's version may already be at the original path. Neither copy is silently discarded.

The executable accepts a `.jot`/`.txt` path or `--open-file <path>` and forwards it to the running instance. Windows **Open with → Jot.exe** works for this development build. A future installer offers optional `.jot` registration and a `.txt` Open with entry without taking over the default text editor. No installer was built. On this machine, the user explicitly approved a per-user `.jot` association repair on 2026-10-03; `.txt` and other file types were not changed.

The designed `.jot` document icon is included as `assets/jot-file.ico`; its preview is `assets/jot-file.png`. Explorer chooses a file icon through the Windows file association, not through the file's contents. The diagnostic found `.jot` using `jot_auto_file`, pointing to the older `dist\Jot-dev-files\Jot.exe`, with no `DefaultIcon`. After explicit approval, only that per-user open command and icon were updated to `dist\Jot-dev-documents-reviewed`. Windows' own association query confirmed both paths, and Explorer received an association-change notification. The protected UserChoice and other file types were untouched. Backup and guarded restore scripts are in `artifacts/file-association-20261003/`. Do not remove or move the registered build without first updating its association.

The application stays neutral in both themes. Each note’s **More → color palette** independently selects from the 19 existing design-system accents for its header and tab. Tabs combine soft tints with an accent strip; the writing surface stays neutral. Existing notes retain their previous accent during migration. New note headers start crimson. Colors survive editing, reloads, and global theme changes.

Global Settings exposes **Theme**, compact **Open mode**, **Auto-save files**, **Writing defaults**, **Keyboard shortcuts** and Quit Jot. ## Taskbar menu

Right-click the running or pinned **taskbar** icon for exactly **Home, New note, Settings**, with small matching home/plus/gear icons. No Show/Hide all, recent-note list, extra commands or shortcut labels are added. Windows supplies the surrounding Jump List style and standard app/Pin/Unpin/Close controls; the app does not replace or hook Explorer's menu. The [Windows Jump List API](https://learn.microsoft.com/en-us/dotnet/api/system.windows.shell.jumplist?view=windowsdesktop-10.0) provides this integration.

Each task works from a closed app and from an already-running instance. Home and Settings reuse one library window without creating or reopening notes; New note creates a note using the saved Tabs/Separate windows preference. Existing note windows/tabs are left intact. A bounded same-user, same-login-session command pipe forwards secondary launches, without coalescing rapid New note requests or accepting arbitrary paths/content. Normal launches still restore the previous work session. Explicit shell tasks do not also run normal startup restoration. Command failures are logged locally. Test/export processes do not register a Jump List or touch the live instance.

Jot uses the stable taskbar identity `Jot.PersonalNotes`; installer shortcut metadata is prepared for it, but no new installer was built. Quit the old running app and launch the current development build once to register its menu. If a pinned shortcut targets an older executable, unpin that shortcut and pin the new running Jot. Glyph variants follow the Windows taskbar theme rather than Jot's note theme. This menu is separate from the tray menu below.

## Custom tray menu

Right-click Jot's tray icon for a compact, custom-templated light/dark menu with the app logo and four actions: Home, New note, Settings, Quit Jot. It is 212 DIPs wide with 32-DIP action rows, no shortcut labels, and no forced first-row focus outline on mouse opening. It is a lightweight WPF window, not a native Windows context menu or another WebView. It has no taskbar entry, supports Escape and arrow-key navigation, dismisses on deactivation, and positions beside the clicked tray anchor at the current monitor's work-area edge. Placement handles top/bottom/left/right taskbars, scaling and negative monitor coordinates, and repositions if error text expands the menu. The window is invisible until positioned. The exact anchor is the visible menu's bottom-right corner meeting the visible icon's top-left corner, with zero gap. Shell_NotifyIconGetRect identifies the tray cell; the current-DPI small-icon metrics and actual ICO alpha bounds remove cell/transparent padding. The menu's real WPF border is measured in screen pixels, so its shadow margin is not guessed. The menu grows upward/left from that point and flips/clamps only at the screen boundary. If Windows cannot supply bounds, it uses the click point. The small NotifyIcon identity adapter is verified against the bundled .NET 10 fields and has a safe fallback. The popup alone is temporarily topmost while visible and explicitly acquires foreground on the user click; dismissal clears its topmost state. This never changes any note's Pin setting. A non-action focus target clears the previously selected row on every open. Settings uses the standard Lucide gear instead of sliders. Settings reuses the index window. New note and Quit show a pending indicator; a failed save keeps Jot running and shows a retryable error.

Jot keeps its tray icon registered while running, but cannot promise placement outside Windows' overflow area. [Microsoft documents that only the user can promote an icon out of overflow](https://learn.microsoft.com/en-us/windows/win32/shell/notification-area). Drag Jot's icon beside the clock if needed. Windows-settings links have been removed from Jot. The app does not change Explorer registry settings or other apps' icon preferences.

Jot uses the approved **three-color faceted stack**: yellow, teal and blue papers with angular folds and diagonal shading. The exact approved color PNG is used by Home and app branding, and packaged into native 16, 20, 24, 32, 48, 64, 128 and 256px ICO frames for the executable and taskbar. A matching monochrome alpha master provides identical silhouettes in dark/light tray inks. The artwork is image-based; the packer resamples and tints it without reconstructing logo geometry. Other interface icons remain Lucide. The source lock, generation prompts and actual-size review sheet are in docs/icon-design. Re-pin a shortcut to this build if it still targets an older executable.

## Responsiveness and initial paint

Typing uses ProseMirror transactions and structural history rather than whole-document DOM snapshots. Direction/token decisions are cached for unchanged nodes and isolation decorations update only affected text blocks. HTML/plain text are captured at save boundaries, not on every key. Native flush first drains pending editor/clipboard/image work. Unchanged notes do not rewrite storage. Autosaving content does not reapply preferences or recolor all open editors. The index updates existing rows, batches search/refresh work, and defers autosave refreshes while hidden.

Typing no longer refreshes the tab strip when the displayed title and file state have not changed. The workspace owns its tab rendering to avoid duplicate updates, and closed tabs release their editor undo/scroll caches. These are targeted reductions in unnecessary work, not a guarantee that a rich-text WebView app matches Windows 10 Notepad's startup, memory use or latency.

The native host disables browser input when its window is hidden or minimized. A separate process-scoped guard makes Jot's fully transparent WebView composition surface click-through, including when that invisible surface remains present after minimization. It does not hide the graphics-capture surface, change an ordinary visible popup, install a desktop mouse hook or alter another app's windows. This addresses the path where an invisible Jot renderer could intercept desktop clicks while the app appeared out of the way.

The app remains C#/.NET 10. See [the measured responsiveness assessment](docs/responsiveness-assessment.md) for the shipped improvements and a direct-rendering experiment. Window movement/resize parity with Telegram has **not** been established; the production capture-based renderer is unchanged, and the experimental host is test-only.

SQLite reads and transactions share a per-store background-worker gate, so SQL, serialization and durable disk flushes do not run on the window dispatcher. Autosave updates only the edited note. The index queries summaries without reading rich HTML or original images; each editor queries its own note, and preferences are queried separately. Failed transactions roll back. There is no stale in-memory data cache hiding external database damage. Original image handling and deleted-note JSON recovery remain unchanged.

New note windows remain transparent and non-activating until the editor has applied its actual theme and crimson/chosen header color. Initial header transitions are disabled; normal transitions resume afterward. This prevents the neutral-white-to-crimson flash without changing the note design. Initialization failures reveal the error state instead of leaving an invisible window.

App/taskbar artwork has a tighter crop (about 1.5% padding, rounded to pixels, versus 6% previously). Tray padding is unchanged. Color and light/dark tray ICOs are packaged at build time and loaded directly at runtime; opening Jot no longer rerasterizes the source artwork. Keep all three ICO assets with the build.

See TESTING.md and the isolated `performance.json` reports for measured results and limitations. The native scheduling changes follow [Microsoft's WebView2 performance guidance](https://learn.microsoft.com/en-us/microsoft-edge/webview2/concepts/performance); measurements here are local synthetic workloads, not guarantees for every device or document.

## Image-window stability

The recorded crash was a late activation/deactivation callback accessing a WebView2 control after disposal. The window now closes its message boundary and detaches callbacks before disposal; queued callbacks/replies are ignored, startup waits are cancelled when the window closes, and ordinary note closing remains save/hide. Image viewers load preferences only, retain original-resolution images, and show a local error for an undecodable image. This fixes the confirmed disposed-viewer path; it does not claim every possible future crash is impossible.

Microsoft documents that accessing [CoreWebView2 after disposal throws](https://learn.microsoft.com/en-us/dotnet/api/microsoft.web.webview2.wpf.webview2.corewebview2). Diagnostics now include process ID and version as well as the existing private-content-safe stack metadata.

## Clipboard recovery and error logs

Native clipboard writes wait briefly for the embedded browser to release its copy operation, then retry temporary `CLIPBRD_E_CANT_OPEN / 0x800401D0` failures with bounded backoff. Newer Jot copy requests supersede older queued requests. A copy error is not a failed note save.

Future errors are logged locally in **%LOCALAPPDATA%\Jot\logs\jot-errors.jsonl**. Logs rotate through three numbered backups, at approximately 1 MB per file. Entries include UTC time, operation, exception type/HRESULT, source filenames and frame locations, retry/recovery events, and renderer error metadata. Note text, clipboard/image payloads, raw exception messages, URLs, and absolute source paths are not recorded. Logging failure cannot interrupt editing. The logs stay on this computer.

## Notifications

Jot's dependency-free notification adapter follows the actual Web design system in `D:\Platform\Web\components\ui\sonner.tsx`, `components\feedback\responsive-toaster.tsx`, `app\globals.css`, and Sonner's packaged styles. Notifications use a neutral popover surface, subtle border, muted 12px title and 11.2px description, with **no X/dismiss icon**. Only an error's icon is red; success notices do not introduce green overlays. They appear at the **bottom right inside the Jot window**, above any writing/footer controls, including in compact notes.

Showing a notification never takes writing focus. Ordinary notices expire after five seconds and errors after eight seconds; loading notices remain while their operation is pending. Hover or keyboard focus pauses expiry. Notifications are keyboard-focusable, announce their content to assistive technology, and **Escape dismisses the focused notice**. At most three notices are visible: newer errors take priority while earlier notices stay queued, and a focused notice or running action is never displaced. Notifications remain accessible above an open dialog and respect reduced-motion settings. Validation that belongs to a form stays inline in that dialog. A file auto-save failure also retains its persistent paused/error file status; dismissing or expiring the toast does not mark the file saved or discard the error.

## Pasting into Codex

Text and images can be included in one prompt, but importing mixed rich HTML in a single paste depends on the receiving composer. Jot now supplies native image data as well as text when exactly one image is selected. End-to-end mixed paste into Codex was not verified because testing must not interrupt the live app. For separate text/image pastes, select a text-only passage and copy it, then open each thumbnail and use Copy image. Receiving apps choose which representation they support. Image inputs are documented at https://learn.chatgpt.com/docs/image-inputs.

## Shortcuts

Open **Settings → Keyboard shortcuts** (Ctrl+Shift+P by default) for a dedicated searchable page with Back to Settings, editing/file commands, app navigation and standard Windows controls. Click an editable app, file or Windows binding to record a key combination, then Save. Clear leaves that action unassigned; Reset restores its default, and Reset all restores every configurable binding after confirmation. Custom choices persist across restarts and update shortcut labels in file menus. Standard text-editing and Windows reference entries are not editable.

These are the default bindings; the shortcuts page shows your current choices:

- Ctrl+N creates a note in the selected Open mode; Ctrl+T explicitly creates a Home-workspace tab, even from a separate note.
- Ctrl+Shift+T reopens the last closed note tab from the current session's bounded history, restoring its tab position and pinned state when possible.
- Ctrl+W closes the current note or closable tab, keeping the permanent Home tab. Ctrl+Tab / Ctrl+Shift+Tab cycle workspace tabs; Ctrl+1–8 selects by position (Home is first), and Ctrl+9 selects the last tab.
- Ctrl+, opens Settings; Ctrl+Shift+H opens Home; Ctrl+Shift+P opens the shortcuts page.
- Ctrl+O, Ctrl+S and Ctrl+Shift+S retain Open, Save and Save as. Standard editing keys remain supported. Cut→Undo restores rich formatting and the original selection, including backward selections; redo restores the post-cut caret.
- Optional **Windows shortcuts** are off by default: Ctrl+Alt+N creates a note and Ctrl+Alt+J shows Jot from another app while Jot is running. Both combinations can be changed or cleared. Conflicts are reported visibly; a failed rebind rolls back to the previous registrations instead of partially applying the change. Disabling the option or exiting releases the registrations. Isolated tests never register real Windows hotkeys.

Duplicate assignments are rejected across app, file and Windows actions. Ordinary typing keys, native editing combinations and Windows-owned controls are protected; app/file bindings cannot consume Ctrl+Alt combinations used for AltGr typing. The recorder captures a physical key consistently across English/Persian layouts, without triggering the action while recording. App shortcuts preserve composition and modal-dialog keyboard ownership. Escape dismisses menus/dialogs, not the app. Image-viewer F11/zoom shortcuts remain unassigned; the buttons and image context menu remain available.

The custom X in a standalone note saves/hides only that note. The workspace window's X saves its remaining note tabs, active tab, Settings-tab state and bounds before hiding, so closing the whole workspace does not mean closing each tab. Windows system-close commands (taskbar Close / Close all windows, or Alt+F4) use the full app Quit path. Image viewers are not restored.

Closing flushes the current DOM, including final composition and in-flight image insertion. User input is held while closing, but pending insert operations may finish before the final snapshot; an earlier autosave cannot replace newer content. Save failures leave the editor available. **Quit Jot** is available from Settings or the tray, and closing the last app window also quits. Quit waits for accepted note creation, file and library operations before saving the session; repeated Quit requests share one operation. A failed save cancels quitting and unlocks editors. Individually closed standalone notes and explicitly closed tabs are excluded from restoration.

## Deleting a note

Use **More → Delete** in its writing window. Confirmation defaults to Cancel. Deleting first saves the latest draft, writes a full recovery copy (including original images) to **%LOCALAPPDATA%\Jot\trash**, then removes the note from the index and closes only its window. Failed saving, recovery copying, or store replacement leaves the live note available. Other notes are unaffected, and stale saves cannot resurrect the deleted note. Recovery copies are retained locally; there is not yet an in-app restore screen.

## Data

Notes now use **%LOCALAPPDATA%\Jot\jot.db**, a local SQLite database with separate notes, groups, settings, and application-state tables. It runs inside Jot; no database server or service is required. The interface remains compatible with the existing version-2 note model. Rich HTML and original embedded images remain together in each note's HTML; this release does not redesign image storage.

On first access, an existing **notes.json** is validated and imported into a temporary database, checked, and only then published as **jot.db**. IDs, order, titles, groups, colors, timestamps, preferences, bilingual content and embedded images are retained. The original **notes.json** and **notes.json.bak** are not changed or removed. Existing databases are authoritative: corrupt or unsupported databases are not silently replaced with older JSON. The earlier prototype's localStorage import remains available when its profile is present.

**jot.db.bak** is a verified SQLite snapshot: migration creates one, an existing store is backed up before its first mutation in a new session, and Quit refreshes it after all notes are saved. Backups use SQLite's backup API, not a live file copy. WAL mode may also create **jot.db-wal** and **jot.db-shm**; never delete or separate them from the live database. Quit Jot before copying its data folder manually. See [SQLite storage and recovery](docs/sqlite-storage.md).

The visible standalone-note session and workspace tab/Settings state are stored transactionally in the SQLite app-state row after editors flush, then included in the Quit backup. The workspace also saves its session before its window X hides it. Missing/deleted notes are excluded from restoration, and invalid session data fails without creating or overwriting notes. A startup restoration failure exposes Home with an error so notes remain accessible. This records orderly close/Quit behavior, not crash recovery for force-killed processes.

Core editing and all UI assets work locally. Network access is only used to retrieve an HTTPS image explicitly included in pasted content; no account or sync service is used.

## Build and test

Keep the source, test code, assets, scripts, documentation, Git history and current `dist/Jot-dev-editorcn` review build. `bin`, compiled `obj`, `node_modules` and `assets/editor` are generated. The pnpm dependencies now build the local React/editorcn/Tiptap editor; Node/pnpm are not needed by the published Windows app. Historical reports/screenshots remain in `test-results/verification-evidence-*.zip`. Preserve old builds referenced by Windows registrations, the existing installer, verified runtime CAB and recovery archives. Publish to a different directory if the target executable is running.

Two old prototype browser profiles found inside build output were preserved as verified ZIPs in the ignored `recovery` directory before cleanup. Keep these recovery copies until their legacy data is no longer needed. Current notes remain under `%LOCALAPPDATA%\Jot`, outside the repository.

    pnpm install --frozen-lockfile
    pnpm run check:editor
    dotnet publish .\Jot.csproj -c Release -r win-x64 --self-contained true -p:JotOfflinePackage=false -o dist/Jot-dev-editorcn
    node --check .\renderer.js
    Start-Process .\dist\Jot-dev-editorcn\Jot.exe -WindowStyle Hidden -Wait -ArgumentList '--self-test','--test-output','.\test-results\manual'

The self-test mode uses isolated data and offscreen non-activating windows, registers no global hotkey, and creates no tray icon. It never writes the user's clipboard. Clipboard formats are tested as in-memory DataObjects and renderer DataTransfer objects. Reports and UI renders stay inside the specified test directory. Use a fresh output directory for each run: failure-injection fixtures deliberately leave broken paths and files behind.

### Keep generated output small

Preview cleanup with an explicit development build to retain, then add `-Apply` to remove unused generated output:

```powershell
.\scripts\clean-generated.ps1 -KeepBuild 'dist\Jot-dev-editorcn'
.\scripts\clean-generated.ps1 -KeepBuild 'dist\Jot-dev-editorcn' -Apply
```

The helper rejects source files, linked paths, nested repositories and possible note data in build outputs. It automatically preserves running Jot builds and builds referenced by the `.jot`/`.txt` or Jot Open with registrations, and rechecks processes and associations before deleting each target. Use `-KeepAdditionalBuilds` for any other build that must stay, including a shortcut-only dependency. Reports/screenshots are archived and hash-verified before their synthetic test stores/profiles are removed. Source, all retained builds, installer, recovery archives, association-repair evidence, native-input diagnostics and existing evidence ZIPs are hash-checked afterward. The small `obj` restore cache stays; compiled `obj/Debug` and `obj/Release` output can be regenerated. The helper never accesses the real user-note store. Release staging and expanded WebView2 copies can be regenerated from the retained, checksum-verified CAB without downloading it again. Do not keep a pinned shortcut pointing to a removed build; use the current executable above.
